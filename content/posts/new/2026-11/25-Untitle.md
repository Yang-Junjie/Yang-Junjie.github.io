## Mizuki 框架

其实我现在不知道应该说什么，但是我感觉我不说的话最近的一些想法、思考、情感问题就会彻底消失，我不想让这些东西消失，虽然其中有美好的，也有坏的。我现在唯一想说的就是就是与我现在正在做的事相关的：“写 blog”。最近我开发了一个新的 blog 框架 [Mizuki](https://github.com/Yang-Junjie/Mizuki) 是为了代替我之前使用的 Astro 框架，其主要原因是因为我使用的 Astro 框架下的 [Shirone](https://github.com/LyraVoid/Shirone) 主题太重了，我的垃圾电脑在写文章的时候实时构建起来非常的慢，并且内存占用空间非常大，让我非常的难受，其实这个问题是主题太重导致的，而我用不上这个主题上的大部分功能（我只是想要一个能写东西的地方，并且简约好看，满足我审美，满足我的基本需要的功能就行，我不要什么花里胡哨的相册功能，我的相册会放在其他地方比如 x），我完全可以只开发一个我自己喜欢的主题即可，没必要开发框架。现在你阅读的这个网站就是用这个框架构建的。


那么我为什么想开发一个框架呢？其主要原因还是因为我是个程序员，当我遇到一些问题的时候，我经常会这么想，能不能自己写一个呢？然后就想到了自己写一个 blog 框架（其实这和我的兴趣爱好有关，在 **关于** 中我提到我喜欢开发创作者工具，因为这能提供更高的自由度，我不喜欢把功能写死的软件），说干就干，带着硬核与 Just For Fun 的精神我直接选择我最熟悉的 `C++` 编程语言编写这个框架，在一开始我选择了手写，不出一个晚上我就得到了一个将 markdown 转换为 html 的程序 (使用 [md4c](https://github.com/mity/md4c) 你可以轻松做到) 再结合 `css` `js` 等前端技术你能得到一个效果不错的网页，或者说 blog. 但是这是一个框架吗？很显然它不是，他就是个文件转换器。在那个时候我目标是一个能够及时热更新的写 blog 的平台，并且构建出的 blog 是我喜欢出的样子。作为一个程序员，这点拆解能力还是有的，我需要一个 build system 还有一个 hot update system 能通知 浏览器 我本地的文件发生了变化，并刷新浏览器。我们需要一个线程能 watch 文件是否发生变化，我们可以使用 [efsw](https://github.com/SpartanJ/efsw) 这个库，当检测到我们的写作工作区文件发生变化时就通知主线程进行 build，我们刚开始是全量构建,得益于 C++ 的高性能 80 多篇文章也能很快构建完，如果我们使用的是 `serve` 指令启动的 `Mizuki` 那么我们还会在构建完后使用 SSE 通知浏览器刷新（我们可以使用 [cpp-httplib](https://github.com/yhirose/cpp-httplib) 这个库做到），由于我没有太丰富的网络编程的经验，所以这部分我那时候是用 AI 完成的。花了一天时间我完成了这些功能，使用 `mizuki serve` 能够启动本地实时修改预览热更新的能生产静态网页的基本的 blog 小框架。

很显然我不想局限于此，开发 blog 框架不是我的主业（我喜欢的是开发计算机图形学软件、撰写图形学文章、学习图形学等等）。但是还有很多如果想让 `Mizuki` 变得完善的功能需要添加，比如主题功能，主题模板，增量更新，图片压缩，以及各种框架核心需要提供给主题的小功能。我不能把我的精力花在这，所以你懂的我使用了 GPT 6.2 sol 进行 vibe coding，在不到一天的时间内 gpt 就完成了大部分工作。与我之前进行 vibe coding 不同，这次我让 AI 去参考现的优雅的、完美的、规范的项目的代码风格，合理使用设计模式等等，具体的当时的 Prompt 如下:

``` text
我们现在专门做一轮项目、代码清理，请你找出堪称完美、被世人所评为优雅的代码、项目的风格作为参考对我们的项目做一下清理，你可以随意重构我们的代码，不仅仅是风格，还有设计你也可以让其变得更优雅，合理使用设计模式，你先理解我的问题，并查阅资料，待我确认后再开始
```

在这个 prompt 下我们 vibe 出来的代码不算屎山，我不知道代码量上去后还是否能约束好有一个好的收敛 `Mizuki` 的代码量还不算大，随后我们进行迭代开发她参考了许多 `Hugo` 与 `Zola` 的设计。最后得到了我们现在的 [Mizuki](https://github.com/Yang-Junjie/Mizuki) 以及其使用自身构建的 [文档站](https://blog.cglab.top/Mizuki/)。我现在就是在用 `Mizuki` 写 blog 这种感觉非常的好，并且她的构建速度我异常的满意我能在浏览器上瞬间看到更新后的文章，不过体验较差的是浏览器刷新后不能定位到上次的位置，会回到页面的顶部。除此之外我认为对于我来说没有任何缺点了，她已经满足我自己的所有需求了（也许我们应该再加一个每个文章的字数统计的功能，因为我还挺想看我写了多少字的，还有置顶文章？不过这在主题中应该能做到）。

开发 `Mizuki` 框架给我带来的收获嘛？最大的收获肯定是获得了一个我自己喜欢的写作平台，其次是开始接触网络编程了（这太无聊了），获得了一些主题模板开发的经验。并且我找到了一个非常好的库啊，就是 [efsw](https://github.com/SpartanJ/efsw) 可以观察文件是否发生变化，这个非常的好啊，在我游戏引擎的编辑器的 Asset System 中我需要这个功能判断是否应该重新导入资源。呃..应该就没了吧，还有就是让我想更进一步学习 C++ 多线程、高性能编程。`Mizuki` 未来的打算？我打算等我写 blog 时实际遇到问题后再尝试开发新的功能，不过我现在想做的就是提升构建速度，图片压缩速度还是太慢了，也许我们的目标是打败 `Hugo` 。

我们的 [CGLab](https://blog.cglab.top/) 的前端设计参考了 [雪萌天文台](https://blog.snowy.moe/) ，看了很多主题的设计还是觉得雪萌天文台的设计最符合我的审美。雪萌天文台的站长是我同校的同学，这个人我觉得挺有意思的，不过 ta 生病了比较难受吧，我也不知道怎么办，我已经没有很多精力去处理太多精神病患者的关系了，我们还是做普通的同学关系比较好，祝 ta 天天开心吧！

## Galgmae 式人生
啊，写完了上面的又不知道写什么了，明明之前来感觉的时候非常想写，但是已经忘了，情绪已经褪去了。人的记忆还是太不可靠了，但我认为这是好事，你能让你忘记某些事情，你要知道人是一个有情感的动物，如果我们能将所以的东西记下来（这也许是很多人想要的超能力之一）那么我们就会记住很多痛苦的事情，虽然是记住了但不会给你带来情绪问题，时间过了很久你依然记得第一次分手的时候的场景，但你不会再为此伤心不是吗？所以我又在左右脑互相博弈，无论怎么说，我觉得人现在这样挺好的，I accept。

在 [Mizuki 部分](#mizuki-框架) 中的最后我提到我的精力很有限，那我们现在聊聊也是我以前闪过的一个小观点，就是我们的生活需要和 galgame 类似。就像 galgame 或者其他游戏一样，我们的一天的时间内，或者说一周内精力都是有限的，我们需要合理的分配这些精力（其实这里我们使用形式化语言去描述会更准确，我也认为会更好理解，但还是算了吧。说句题化话，我注意到我的笔记本电脑显示器边框上的封条胶条烂掉了T^T）如果分配的有问题的话你会很累，或者被压垮。在精力被耗尽的情况下去工作，只会适得其反并且你会非常难受，注意力根本集中不了。

所以合理的、科学的分配管理精力是非常必要的，甚至是必须的。~~你们可能知道 [我的 Github](https://github.com/Yang-Junjie) 几乎每天都有 commit 一方面是我喜欢做这些事，另一方面我们需要坚持，但这好像和精力无关，因为这是长期的，没错我不打算删掉这段，因为这篇 blog 我想随便写。~~ 通常我们都会有很多任务、代办等待着我们去完成，为了完成我们的伟大目标，我们需要合理的分配我们有限的精力去完成这些任务，当然我们也需要科学的管理这些任务。对我又打算写议论文了，这不行，我不写，总之我们需要像玩 galgame 一样玩自己，在精力耗尽的时候去休息，最后每周都能出去放松一下，保持身心健康，才能可持续的完成我们的目标，比如写 [Vulcal Engine](https://github.com/Virtual-Graphics/VulcalEngine) .

除此之外，人之间的关系也一样需要像 galgame 一样需要培养的啊 .>_<. 你不能丢下一个人放在那不管，她会伤心，她会胡思乱想，她会每天都想你，而你却对她爱答不理，好感度下降是必然的。除非你和她的关系已经上深到了非常高的阶段，这样就不用管了。我们人是有好感度这种东西的啊，需要提升好感度的啊，会玩 galgame 怎么不会玩我呢？？我好难过啊。。。当关系下降后也就是好感度下降，也需要通过类似 galgame 的方式提高好感度啊。

现实世界没有和 galgame 类似的读档功能，所以好好对待你爱的人吧。别等她心碎了再尝试挽留。
